# Inbound email raw-message bound

The IMAP importer accepts at most **50 MiB (52,428,800 bytes)** of total raw RFC822 source, including MIME/base64 overhead, headers and body. Existing decoded attachment type/count/size checks still run afterwards. This intentionally rejects some messages whose decoded attachments would otherwise fit; it caps normal per-message downloads and parser input rather than only saved attachments.

ImapFlow 2.0.5's installed `dist/cjs/types.d.ts` declares `FetchQueryObject.size?: boolean`, `FetchMessageObject.size?: number`, and `source?: Buffer`; its fetch implementation requests RFC822.SIZE when `size: true`. The importer requests UID, size and internal date without source, validates UID/date and a positive safe integer size, then fetches source once. Missing/invalid size is a permanent safe skip. A second actual-buffer-length check prevents parsing unexpectedly oversized source. A server that lies about RFC822.SIZE can still cause that buffer allocation; this is a metadata trust boundary, not a streaming hard memory ceiling.

Skipped messages remain in the mailbox, without setting Seen or deleting/moving them. A durable diagnostic uses the existing ImapSyncRetry row keyed by sync/account/mailbox/UIDVALIDITY plus UID: **attempts=0 is reserved for terminal skips**, with a far-future timestamp and fixed JSON status/reason/size/limit. No sender, subject, source or credential is recorded. Console warnings have the same safe fields plus UID. Retry queries require attempts>0, and completion cleanup preserves terminal markers. A terminal marker is checked before metadata or source download, including replay after a checkpoint reset. Returning false advances scanning without counting an import or failure. A diagnostic write failure follows the ordinary retry path, so a skip cannot be silently lost.

These diagnostic rows are not pending retry jobs: operational retry counts must filter attempts>0. No schema migration, queue cleanup, or production-record deletion is part of this change. Fixture tests create random dedicated sync IDs and delete only those fixture states (cascading their own markers).
